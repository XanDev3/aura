## What Is x402

x402 is an open payment standard (Apache-2.0) that uses the long-reserved HTTP `402 Payment Required` status code to enable direct, programmatic micropayments between clients and servers — no accounts, no credentials, no credit card rails. Payment is settled onchain via EIP-3009 gasless USDC transfer.

**Core participants:**
- **Seller (server):** API or service that returns 402 with payment requirements
- **Buyer (client):** Developer or AI agent that signs and submits payment
- **Facilitator:** Third-party service that verifies the signed authorization and settles it onchain

---

## Protocol Flow (6 Steps)

```
1. Client → Server:   POST /api/analyze  (no payment header)
2. Server → Client:   HTTP 402  (body: payment requirements JSON)
3. Client:            Signs EIP-3009 authorization (no gas needed)
4. Client → Server:   POST /api/analyze  (header: PAYMENT-SIGNATURE: <base64>)
5. Server → Facilitator: POST /verify + POST /settle
6. Server → Client:   HTTP 200  (header: PAYMENT-RESPONSE: <base64>)
```

**Headers (V2 — use these, NOT V1 names):**
| Direction | Header | Description |
|-----------|--------|-------------|
| Client → Server | `PAYMENT-SIGNATURE` | Base64-encoded signed payment payload |
| Server → Client | `PAYMENT-RESPONSE` | Base64-encoded settlement confirmation |

**V1 → V2 rename:** `X-PAYMENT` → `PAYMENT-SIGNATURE`, `X-PAYMENT-RESPONSE` → `PAYMENT-RESPONSE`

## Server Implementation (Next.js — AURA Pattern)

### Critical: Edge Runtime vs Node.js Runtime

`middleware.ts` runs in **Edge Runtime** — it CANNOT use Node.js crypto APIs. `@x402/evm` uses `crypto.createSign` and will crash in Edge Runtime. **Always put x402 server logic in route handlers, not middleware.**

```
middleware.ts         → Edge Runtime  → NO @x402/evm here — will crash
app/api/*/route.ts    → Node.js Runtime → @x402/evm works fine
```

The `middleware.ts` at project root must remain a pass-through:
```typescript
// middleware.ts — MUST be a pass-through, x402 lives in route.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(_req: NextRequest) {
  return NextResponse.next();
}

export const config = {
  matcher: [], // no routes intercepted
};
// NOTE: Next.js 16 requires the `middleware` function export even if it's a no-op.
// Missing it → build error: "Middleware is missing expected function export name"
```

### Full Route Handler Pattern (withX402)
```typescript
// src/app/api/analyze/route.ts
import { withX402, x402ResourceServer } from "@x402/next";
import { ExactEvmScheme } from "@x402/evm/exact/server";
import { HTTPFacilitatorClient } from "@x402/core/server";
import { getAuthHeaders } from "@coinbase/cdp-sdk/auth";

// CDP JWT auth — REQUIRED for Base mainnet. HTTPFacilitatorClient does NOT
// auto-detect env vars. Each endpoint needs its own JWT (path-specific signing).
async function buildCdpAuthHeaders() {
  const apiKeyId = process.env.CDP_API_KEY_ID!;
  const apiKeySecret = process.env.CDP_API_KEY_SECRET!;
  const host = "api.cdp.coinbase.com";
  const base = "/platform/v2/x402";
  const [verify, settle, supported] = await Promise.all([
    getAuthHeaders({ apiKeyId, apiKeySecret, requestMethod: "POST", requestHost: host, requestPath: `${base}/verify` }),
    getAuthHeaders({ apiKeyId, apiKeySecret, requestMethod: "POST", requestHost: host, requestPath: `${base}/settle` }),
    getAuthHeaders({ apiKeyId, apiKeySecret, requestMethod: "GET",  requestHost: host, requestPath: `${base}/supported` }),
  ]);
  return { verify, settle, supported };
}

const facilitatorClient = new HTTPFacilitatorClient({
  url: process.env.X402_FACILITATOR_URL || "https://api.cdp.coinbase.com/platform/v2/x402",
  createAuthHeaders: buildCdpAuthHeaders,
});

const x402Server = new x402ResourceServer(facilitatorClient)
  .register("eip155:8453", new ExactEvmScheme());

async function handler(req: NextRequest): Promise<NextResponse<unknown>> {
  // ... your actual endpoint logic
}

export const POST = withX402(
  handler,
  {
    accepts: [
      {
        scheme: "exact",
        price: "$0.01",            // Dollar format string
        network: "eip155:8453",    // CAIP-2 — Base mainnet
        payTo: process.env.AGENT_WALLET_ADDRESS!,
      },
    ],
    description: "AURA DeFi Analysis — 0.01 USDC per query",
    mimeType: "application/json",
  },
  x402Server
);
```

### RouteConfig Interface
```typescript
interface RouteConfig {
  accepts: Array<{
```

## Client Implementation (Buyer — AURA Test Script Pattern)

```typescript
import { x402Client, wrapFetchWithPayment } from "@x402/fetch";
import { registerExactEvmScheme } from "@x402/evm/exact/client";
import { privateKeyToAccount } from "viem/accounts";
import { createWalletClient, http } from "viem";
import { base } from "viem/chains";

const account = privateKeyToAccount(process.env.AGENT_PRIVATE_KEY as `0x${string}`);
const walletClient = createWalletClient({
  account,
  chain: base,
  transport: http(),
});

const client = new x402Client();
registerExactEvmScheme(client, {
  signer: {
    address: account.address,
    signTypedData: async (typedData: any) => walletClient.signTypedData(typedData),
  },
});

const fetchWithPayment = wrapFetchWithPayment(fetch, client);

// Use exactly like fetch — 402 handling is automatic
const response = await fetchWithPayment("https://your-api.com/endpoint", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ query: "..." }),
});
```

**Note:** `@x402/fetch` / `@x402/evm/exact/client` do NOT use Node.js crypto — safe anywhere including Edge Runtime and browser.

## Lifecycle Hooks

Hooks let you customize payment behavior without modifying core flow.

### Server-Side: x402ResourceServer
```typescript
const server = new x402ResourceServer(facilitatorClient)
  .register("eip155:8453", new ExactEvmScheme());

// Block payment before verify (e.g., denylist check)
server.onBeforeVerify(async ({ paymentPayload }) => {
  if (isDenylisted(paymentPayload.from)) {
    return { abort: true, reason: "Address blocked" };
  }
});

server.onAfterVerify(async ({ paymentPayload }) => {
  // Logging, analytics
});

server.onVerifyFailure(async ({ error }) => {
  // Return { recovered: true, result } to override failure
});

server.onBeforeSettle(async ({ paymentPayload }) => {
  return { abort: true, reason: "..." }; // or undefined to continue
});

server.onAfterSettle(async ({ paymentPayload, settlementResult }) => {
  // Update revenue tracking, write to KV
});

server.onSettleFailure(async ({ error }) => {
  // Return { recovered: true, result } to override
});
```

### HTTP Server Hook: x402HTTPResourceServer (via withX402)
```typescript
// Access via the x402Server instance before passing to withX402
x402Server.onProtectedRequest(async (context) => {
  // Grant access without payment (e.g., API key holders)
  if (context.headers["x-api-key"] === ADMIN_KEY) {
    return { grantAccess: true };
  }
  // Block with 403
  if (isBlocked(context.ip)) {
    return { abort: true, reason: "Blocked" };
  }
  // return undefined to proceed with normal payment flow
});
```

### Client-Side: x402Client
```typescript
client.onBeforePaymentCreation(async ({ paymentRequired }) => {
  // Enforce spending limit
  if (parseFloat(paymentRequired.price) > MAX_SPEND) {
    return { abort: true, reason: "Exceeds spending limit" };
  }
});

client.onAfterPaymentCreation(async ({ paymentPayload }) => {
  // Log payment before submission
});
```

## Idempotency (payment-identifier Extension)

Enables safe retries without double-charging. Use Redis in production.

### Client
```typescript
import { generatePaymentId, appendPaymentIdentifierToExtensions }
  from "@x402/extensions/payment-identifier";

// Generate ONCE per logical request, NOT per retry
const paymentId = generatePaymentId(); // "pay_<32-hex-chars>"

client.onBeforePaymentCreation(async ({ paymentRequired }) => {
  if (!paymentRequired.extensions) paymentRequired.extensions = {};
  appendPaymentIdentifierToExtensions(paymentRequired.extensions, paymentId);
});
```

### Server
```typescript
import {
  declarePaymentIdentifierExtension,
  extractPaymentIdentifier,
  PAYMENT_IDENTIFIER,
} from "@x402/extensions/payment-identifier";

// 1. Advertise support in route config
const routeConfig = {
  accepts: [...],
  extensions: {
    [PAYMENT_IDENTIFIER]: declarePaymentIdentifierExtension(false), // optional
  },
};

// 2. Check cache on protected request
const cache = new Map(); // use Redis in production
const CACHE_TTL = 60 * 60 * 1000; // 1 hour

x402Server.onProtectedRequest(async (context) => {
  const payload = JSON.parse(Buffer.from(context.paymentHeader, "base64").toString());
  const paymentId = extractPaymentIdentifier(payload);
  if (paymentId) {
    const cached = cache.get(paymentId);
    if (cached && Date.now() - cached.timestamp < CACHE_TTL) {
      return { grantAccess: true }; // serve cached response
    }
  }
});

// 3. Cache after successful settlement
x402Server.onAfterSettle(async ({ paymentPayload }) => {
  const paymentId = extractPaymentIdentifier(paymentPayload);
  if (paymentId) cache.set(paymentId, { timestamp: Date.now() });
});
```

## Debugging: Empty 500 Body = Module Init Failure

**Symptom:** Server returns `HTTP 500` with empty body.
**Cause:** Route module threw during initialization (NOT during request handling).
**How to diagnose:** Check Vercel function logs (not HTTP response) — the real error is there.

**Most common cause in AURA:** `HTTPFacilitatorClient` calls `getSupported()` at startup
(`syncFacilitatorOnStart: true` by default). Without valid CDP auth headers → 401 from CDP
→ `validateRouteConfiguration()` throws `RouteConfigurationError` → module fails to load.

**Fix options:**
1. Verify `CDP_API_KEY_ID` and `CDP_API_KEY_SECRET` are set in Vercel environment variables
2. Verify `createAuthHeaders` callback is present in `HTTPFacilitatorClient` constructor
3. Defer init with `syncFacilitatorOnStart: false` to debug timing issues:
   ```typescript
   const x402Server = new x402ResourceServer(facilitatorClient, {
     syncFacilitatorOnStart: false,
   }).register("eip155:8453", new ExactEvmScheme());
   ```

## Token Support

Any ERC-20 that implements **EIP-3009** (`transferWithAuthorization`) can be used. USDC implements this natively. For custom tokens, provide:
- Token contract address
- EIP-712 domain name
- EIP-712 version string

## SDK Feature Parity (TypeScript vs Go vs Python)

TypeScript is the most complete SDK. Key TypeScript-only features:
- `payment-identifier` extension (idempotency)
- `sign-in-with-x` extension (CAIP-122 wallet auth)
- `onPaymentRequired` HTTP client hook
- `onProtectedRequest` HTTP server hook
- `enrichPaymentRequiredResponse` / `enrichSettlementResponse` hooks

Go and Python have parity on: server, client, facilitator, EVM + SVM networks, basic hooks.

## V1 → V2 Breaking Changes (Quick Reference)

| Area | V1 | V2 |
|------|----|----|
| Request header | `X-PAYMENT` | `PAYMENT-SIGNATURE` |
| Response header | `X-PAYMENT-RESPONSE` | `PAYMENT-RESPONSE` |
| Version field | `x402Version: 1` | `x402Version: 2` |
| Network ID | `"base-sepolia"` | `"eip155:84532"` |
| TS package | `x402-express` | `@x402/express` |
| TS buyer fn | `withPaymentInterceptor` | `wrapAxiosWithPayment` |
| TS client | pass wallet directly | `new x402Client()` + `registerExactEvmScheme` |
| Route config | inline fields | `accepts` array with `scheme` + `payTo` |

## Key Lessons (Hard-Won in AURA)

1. **Never put x402 server in `middleware.ts`** — Edge Runtime lacks Node.js crypto. Use `route.ts`.
2. **`HTTPFacilitatorClient` needs explicit auth** — it does not read CDP env vars automatically.
3. **`getAuthHeaders` is path-specific** — generate separate JWTs for `/verify`, `/settle`, `/supported`.
4. **Empty 500 = init failure** — check Vercel function logs, not HTTP response body.
5. **Testnet facilitator ≠ mainnet** — `x402.org/facilitator` only works for Base Sepolia.
6. **Price is a dollar string** — `"$0.01"` not `1_000_000` (the SDK converts to USDC units internally).
7. **`x402Version: 2`** — always use V2 CAIP-2 network IDs, not V1 string names.
